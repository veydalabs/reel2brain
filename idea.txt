## What TRIBE is actually outputting

From the public TRIBE v2 repo, the basic inference call returns:

```python
preds, segments = model.predict(events=df)
print(preds.shape)  # (n_timesteps, n_vertices)
```

The repo says those predictions live on the **fsaverage5 cortical mesh**, roughly **20k vertices**, and are offset by about **5 seconds** to compensate for hemodynamic lag. ([GitHub][1])

More specifically, the BERG model card lists the standard output as **20,484 cortical vertices**, split as **10,242 left hemisphere + 10,242 right hemisphere**, with predictions at **1 Hz**, meaning one predicted cortical activation frame per second. It also says ROI selection can use the **Glasser HCP-MMP1.0 parcellation**, with ROI assignments mapping the 20,484 vertices into labeled cortical regions. ([brain-encoding-response-generator.readthedocs.io][2])

So the structure is basically:

```txt
preds[timestep, vertex_index] = activation_value
```

Not:

```txt
region_name -> activation
```

and not directly:

```txt
x, y, z -> activation
```

The **coordinates come from the fsaverage5 surface mesh**, not from TRIBE itself. TRIBE gives you the changing values. The surface mesh gives you the 3D positions.

## So yes: plot all the coordinates, then make some light up

The clean render pipeline is:

```txt
fsaverage5 vertices:
  vertex_i = [x, y, z]

fsaverage5 faces:
  triangle_j = [i0, i1, i2]

TRIBE predictions:
  activation[t][i]

Renderer:
  draw vertex_i / face_j
  color vertex_i by activation[t][i]
  optionally push vertex_i outward along its normal
```

That means your GPU viewer should treat the brain like a **fixed terrain mesh** with a **time-varying activation texture/buffer**.

The current viewer is probably doing this at some level already, but you can make it feel way more alive by using the predictions as more than just color.

## The cooler version: 4-layer GPU brain engine

I’d build it as four render layers stacked together.

### 1. Cortical surface layer

This is the actual semi-transparent brain mesh.

Each vertex has:

```ts
position: vec3
normal: vec3
roiId: uint
activation: float
```

In the vertex shader:

```glsl
float a = activation(vertexId, currentTime);
vec3 displaced = position + normal * pow(max(a, 0.0), 1.5) * displacementScale;
```

So the cortex subtly **breathes outward** where activation spikes.

Not too much. Just enough to make it feel like pressure moving through tissue.

### 2. Vertex particle layer

One GPU instance per cortical vertex.

This is where it becomes beautiful.

For each of the ~20,484 vertices, render a tiny glowing point/sprite. Its size, opacity, and color come from activation.

```txt
low activation  -> dim ember
high activation -> bright hot particle
peak activation -> bloom flare
```

Then add temporal decay:

```txt
visible_activation[t] =
  max(current_activation[t], previous_visible_activation * decay)
```

Now you get **trails**, not flicker. The brain remembers what just lit up.

That matters aesthetically and analytically.

### 3. Mesh-adjacency graph layer

This is where your Hindsight/network intuition plugs in.

The fsaverage5 surface has triangular faces. From those faces, you can derive edges:

```txt
face [a,b,c] -> edges (a,b), (b,c), (c,a)
```

Then render only edges where both endpoint activations are high:

```txt
edge_intensity = (activation[a] + activation[b]) / 2
```

Now activation doesn’t just appear as blobs. It becomes **electric filaments crawling across cortical topology**.

This would look insane:

```txt
surface heatmap below
particle spikes above
glowing graph arcs between hot neighboring vertices
```

You’d basically get “cortical lightning.”

### 4. ROI supergraph layer

This is the “brain region stuff.”

Use the HCP-MMP ROI assignment array:

```txt
vertex_i -> roi_id
```

Then compute region-level time series:

```python
roi_activation[t, roi] = mean(preds[t, vertices_in_roi])
```

Then compute graph edges between ROIs using coactivation/correlation:

```python
edge_weight[roi_a, roi_b] = corr(roi_ts[:, a], roi_ts[:, b])
```

Now you can show a second graph floating above the cortex:

```txt
node = cortical region centroid
node size = current ROI activation
edge brightness = coactivation / synchrony
```

This gives you two scales at once:

```txt
micro: individual cortical vertices
macro: region-level functional graph
```

That is much cooler than a normal brain heatmap.

## The data package I’d export from Python

I’d make a preprocessing/export step that produces something like this:

```txt
tribe_run/
  metadata.json
  vertices_lh.bin
  vertices_rh.bin
  faces_lh.bin
  faces_rh.bin
  normals_lh.bin
  normals_rh.bin
  roi_assignments.bin
  roi_labels.json
  activations.f16.bin
  transcript_segments.json
  video_timeline.json
```

Important move: store activations as **float16** or even normalized **uint16**.

20,484 vertices × 60 seconds is only about 1.2M scalar values. That is tiny for GPU. Even a 10-minute clip:

```txt
20,484 × 600 × 2 bytes float16 ≈ 24.6 MB
```

Totally manageable.

## The frontend renderer should not think in JSON

For the visualization itself, don’t feed the browser giant JSON arrays. Use binary buffers.

Ideal GPU-side buffers:

```ts
positionBuffer: Float32Array   // [x,y,z] per vertex
normalBuffer: Float32Array     // [nx,ny,nz] per vertex
roiBuffer: Uint16Array         // roi id per vertex
faceIndexBuffer: Uint32Array   // triangle indices
activationBuffer: Float16Array // [time, vertex]
```

At playback time:

```ts
frameA = floor(videoTime)
frameB = frameA + 1
alpha = fract(videoTime)

activation = mix(
  activationBuffer[frameA, vertexId],
  activationBuffer[frameB, vertexId],
  alpha
)
```

That gives smooth animation even though TRIBE itself is 1 Hz.
